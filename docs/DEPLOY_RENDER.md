# Deploying on Render

Three pieces, all described in [`render.yaml`](../render.yaml):

| Render resource | What it is | Public? |
|---|---|---|
| `ms-db` | managed PostgreSQL 16 | no |
| `ms-api` | FastAPI + the Drive auto-sync scheduler (private service, exactly **1** instance) | no |
| `ms-web` | Next.js app; proxies `/api/*` to `ms-api`, so the login cookie stays same-origin | **yes** (the only address you share) |

The private service and the database have no free tier at this size, and `ms-api` needs about 2 GB RAM because it
reads large `.xlsx` workbooks. Plans in the Blueprint are a starting point; change them in the dashboard.

## 1. Create the Blueprint
1. Push this repository to GitHub (already done: `isngs-dev/ms-analytics`).
2. Render dashboard > **New > Blueprint** > pick the repository. Render reads `render.yaml`.
3. It asks for `DRIVE_ROOT_FOLDER_ID` (the id of the "MSS Input" folder in Drive). Paste it.
4. Apply. `ms-db`, `ms-api` and `ms-web` are created. `ms-api` runs the migrations on every start.

`JWT_SECRET` is generated by Render. `COOKIE_SECURE=true` is set because Render serves everything over HTTPS.

## 2. Give `ms-api` access to Drive (secret file)
The sync reads Drive with an OAuth token created by `scripts/drive_login.py` (read-only scopes).
1. `ms-api` > **Environment > Secret Files > Add Secret File**
2. Filename `oauth-token.json`, contents = the file `secrets/oauth-token.json` from your computer.
3. Save. The path `/etc/secrets/oauth-token.json` is already set in `GOOGLE_OAUTH_TOKEN_FILE`.

**The token must not expire.** If the Google Cloud OAuth consent screen is in *Testing*, Google revokes the refresh token
after 7 days and every sync then fails with `invalid_grant: Token has been expired or revoked` (Data Health shows it,
the automatic sync stops picking up new Drive data). Fix it once, permanently: Google Cloud Console > APIs & Services >
OAuth consent screen > **Publish app** (status "In production"; it stays an unverified read-only app for your own account,
which is fine). Then run `scripts/drive_login.py` again and replace the Secret File on Render with the new
`secrets/oauth-token.json`.

A service account JSON works too: add it as a secret file `service-account.json`, set
`GOOGLE_SERVICE_ACCOUNT_FILE=/etc/secrets/service-account.json`, and share the Drive folder with its `client_email`.
Never commit either file. If the token ever leaks, revoke it at https://myaccount.google.com/permissions.

## 3. Load the data
**A. Copy the data you already have (recommended, minutes).** The first full sync of ~550 workbooks takes hours because
Google's read quota is throttled; restoring a dump skips that, and the 10-minute sync then only reads changed files.

```bash
# on your computer, in the project folder (app_user is left out: no demo accounts in production)
docker compose exec -T db pg_dump -U ms -d ms_analytics -Fc --no-owner --no-acl --exclude-table-data=app_user > ms.dump

# Render: ms-db > Connections > "External Database URL"
docker run --rm -v "$PWD":/dump postgres:16-alpine \
  pg_restore --clean --if-exists --no-owner --no-acl -d "<External Database URL>" /dump/ms.dump
```
Then restart `ms-api` (Manual Deploy > Restart). `ms.dump` holds business data: keep it out of git (it is ignored).

**B. Let it sync by itself.** Start `ms-api`, open the site, and wait; progress is on **Data Health**.
Only the years chosen in the kept-years setting are synced (`python scripts/keep_years.py 2025 2026` inside `ms-api`).

## 4. Create your first login
Open `ms-api` > **Shell** and run (the password is read from the environment and never printed):

```bash
ADMIN_PASSWORD='a-long-unique-password' python scripts/create_admin.py you@company.com "Your Name" admin
```
Sign in at the `ms-web` URL, then add everyone else under **Admin > Users**. Do not run `python -m app.seed.users`
in production: it creates the `*@example.com` demo accounts.

## 5. Check
- `ms-web` URL opens the sign-in page; after login, **Data Health** shows the last sync ("Live · checked … ago").
- `ms-api` > Logs: `alembic` finished, then uvicorn started; scheduled syncs appear every 10 minutes.

## Notes
- **One API instance only.** The scheduler runs inside the process; two instances would sync twice. Do not enable autoscaling.
- A deploy or restart of `ms-api` during a running sync marks that sync as failed; the next scheduled run continues
  (unchanged files are skipped), so it is safe, only slower.
- `API_INTERNAL_URL` is baked into the web build. If you rename `ms-api`, redeploy `ms-web`.
- If `ms-web` builds but `/api` calls fail, open `ms-web` > Environment and make sure `API_INTERNAL_URL` shows `ms-api:8000`
  (trigger a **Clear build cache & deploy**).
- If the Google token is not readable (`Permission denied` for `/etc/secrets/oauth-token.json`), the API runs as a
  non-root user: re-add the secret file or check that the file is world-readable in Render's Secret Files.
- Back up the database from Render (Postgres > Backups) once the plan allows it.
